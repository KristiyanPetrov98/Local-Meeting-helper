# M1 implemented architecture

This records implemented M1 behavior. The M0 architecture remains a proposal for later
AI/capture/retrieval components; no M0 feasibility status is upgraded by this work.

Electron main owns the two BrowserWindows, tray, single-instance lock, global shortcut,
content protection request, per-launch token, and Python child process. Preload exposes
only bootstrap, an enumerated command API and native-status subscription. Commands
check the sender window, top frame and exact service origin. Renderers run with context
isolation, sandbox and no Node integration. External navigation/new windows and media
permission requests are denied. Only the explicit browser-dashboard command opens an
external URL generated by the main process.

Python startup binds an OS-selected port on 127.0.0.1, builds the service around that
socket, and reports readiness only after Uvicorn startup. The token and database path
arrive over stdin, not command-line arguments. SQLite WAL, foreign keys, transactions
and a unique live-session index keep one session active across both interfaces.
FastAPI serves built React assets from the same origin. Bearer auth protects state,
mutations and schema. Host/Origin checks reject foreign websites and DNS rebinding;
CSP, nosniff, no-store and referrer policy apply to served responses. No permissive CORS.
This is a local-process trust boundary, not protection against malware with user-level
access. Full security qualification belongs to M7.

Browser bootstrap receives a token via fragment, stores it in per-tab sessionStorage,
and immediately clears the fragment with replaceState. Electron gets the same token
through validated IPC. Token never enters query parameters, API logs or persisted
application settings. WebSocket authenticates its first message (five-second deadline),
requires the exact Origin/Host, and accepts no mutation commands. Server queues at
most one latest snapshot per subscriber. Client reconnects with capped backoff and
rejects older revisions; controls disable when disconnected. State mutation endpoints
return snapshots as well, avoiding optimistic divergence between windows.

## Session state machine

No current live session → active (selected project and consent required).
active → paused → active; either live state → stopped. Session/project association is
immutable. Switching away from or deleting its project is rejected while live. Starting
a second session or applying a stale/invalid transition returns conflict. Start/stop
records are real persisted shell state; **they do not mean audio is captured**. UI,
capabilities and session controls explicitly say capture is unavailable in M1.

On normal quit Electron stops a live session before terminating the child; on restart
any remaining live session is marked interrupted. Dashboard/mini close hides to tray;
explicit Quit ends the app. A child-service failure shows a fatal message and exits;
next launch recovers persisted state. Renderer crashes also request safe shutdown.
Session elapsed time is wall-clock duration including paused periods, not recorded-audio
duration. Most recent 20 sessions are shown with their project names. Deleting a project
explicitly deletes its session history; no document storage exists in M1.

## Native integration and model boundary

Shortcut registration acquires the new binding before releasing the old one. A conflict
keeps the previous binding. Successful configuration is persisted through the API; a
persistence failure attempts rollback. Shortcut invocation only shows/focuses the mini
and reports that AI is unavailable until M4. No synthetic answers or hidden inference.
The companion is always-on-top, draggable, collapsible, dismissible, remembers position,
and clamps to available work areas after display removal. Content protection is set as
defense in depth; Windows sharing exclusion is untested and never guaranteed.

No GPU/model configuration was changed. Qwen3-VL 8B, bounded context and the M0 reserve
remain the primary candidates. M3 will add the independent capture/ASR worker; M4/M5
will consume the same state and scheduler contracts. No model or ASR process is started
by the M1 shell, so this milestone makes no transcription continuity claim.

## Contracts and build

FastAPI OpenAPI snapshot is committed under packages/contracts. openapi-typescript
produces frontend Snapshot/Project/Session types. A versioned state.updated WebSocket
envelope carries that snapshot; native IPC is a separate narrow TypeScript union.
React/Vite/Tailwind build to static assets; a shared Radix/CVA Button follows shadcn/ui
composition. esbuild emits main.cjs and a sandbox-compatible preload.cjs. npm lockfile
pins the JS dependency tree; Python runtime and dev locks include artifact hashes.
Locks were generated/tested on Python 3.12 Linux; Windows installation remains unrun.
No installer is provided before M6.
